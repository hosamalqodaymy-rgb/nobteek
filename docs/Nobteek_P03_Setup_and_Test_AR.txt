نوبتيك — تجهيز المشروع وقاعدة البيانات P03

الحالة الحالية
أغلقت مرحلة الواجهات P02 بنجاح: 126 فحصا للنموذج، إضافة إلى 51 فحص ارتداد P00.
اكتملت P03 واجتازت T03A وT03B: بناء نظيف وترحيلات وبذر واتصال PDO واختبارات تكامل PostgreSQL فعلية.

ما جهز
مشروع Laravel وReact وTypeScript في application، يستخدم الهوية والخط من design دون إعادة تعريفها.
ملفا Composer وNPM للإصدارات المقفلة، وترحيل PostgreSQL، وبذور تجريبية، وبيئتان منفصلتان للتطوير والاختبار.
13 جدولا للحسابات والعضويات والعيادات والأطباء والجلسات والفترات والمراجعين والحجوزات والزيارات والروابط والتدقيق والأحداث ومنع التكرار.
مراجع مركبة تربط السجلات بالعيادة الصحيحة، ورقم دور فريد لكل جلسة، ووصول واحد للحجز، وحالة نشطة واحدة للطبيب.
حسابات البيانات التجريبية معطلة وبلا كلمات مرور؛ روابط المتابعة مخزنة كبصمات فقط. لا توجد واجهات دخول أو حجز فعلي بعد.
لا توجد جداول مالية أو إرسال مدفوع أو استضافة مشتراة. تبقى هذه الأمور في P13.

ما اختبر فعليا
نجحت إعادة تثبيت الاعتماد من ملفات القفل، وتوليد مفتاح محلي جديد، وفحص TypeScript وبناء الواجهة، وتشغيل Laravel من مجلد جديد دون نسخ مفاتيح البيئة السابقة.
نجحت اختبارات Laravel الأربعة عشر، منها 6 اختبارات تكامل PostgreSQL و8 للتشغيل، مع 45 تأكيدا ودون إخفاقات أو اختبارات متجاوزة.
نجحت 31 فحصا داخل محرك PostgreSQL 17.11 في وضع العملية المفردة، منها ترحيل قاعدة جديدة وبذرها مرتين، واختبار المراجع والقيود بصلاحية قاعدة غير فائقة.
نجحت 6 فحوص للمصدر وملفات القفل والاعتماد السابق وصياغة PHP وتهيئة القاعدة.

نطاق التحقق النهائي
جرى الاتصال بخادم PostgreSQL محلي عبر TCP مصادق، وتشغيل ترحيلات Laravel والبذر والاختبارات الكاملة.
نجحت إعادة تثبيت المصدر والبناء والترحيلات والبذر والاختبارات الأربعة عشر من مجلد جديد، دون نسخ مفاتيح البيئة السابقة.
فحصت قاعدتا التطوير والاختبار بحسابين مستقلين؛ نجح ترحيل وبذر كل منهما ورفض اتصال حساب إحداهما بقاعدة الأخرى.
أصلحت مشكلة إعادة تعريف دالة PostgreSQL عند migrate:fresh، ثم اجتازت النسخة المصححة الفحص الكامل والبناء النظيف.
بقيت ملفات CI وDocker غير مشغلة هنا؛ لا تعرض على أنها نتائج تشغيل فعلية. لم ينشأ مستودع أو مورد خارجي.
هذه نتائج أساس المشروع. تنفيذ الحسابات والصلاحيات والحجز والدور الفعلي يبدأ في المراحل التالية، ولا تستخدم بيانات حقيقية قبل الأمان والقبول.

تشغيله على جهاز يسمح بخادم PostgreSQL
1 فك حزمة المصدر وادخل مجلد nobteek/application. يلزم PHP بامتدادات pdo_pgsql وmbstring وxml وdom وcurl وzip، وComposer وNode. يمكن استخدام Docker Compose 2 لتشغيل القاعدتين.
2 نفذ composer install ثم npm ci ثم npm run build.
3 انسخ .env.example إلى .env، وضع كلمة مرور محلية خاصة في DB_PASSWORD. لا ترفع هذا الملف إلى المستودع.
4 نفذ docker compose --profile dev up -d db-dev ثم تحقق أن خدمة القاعدة أصبحت healthy. بيانات التطبيق الافتراضية nobteek_development وnobteek_dev على المنفذ 5432.
5 نفذ php artisan key:generate --no-interaction ثم php artisan migrate --seed --no-interaction.
6 لتشغيل الصفحة استخدم php artisan serve على جهاز التطوير. الصفحة الحالية غلاف فقط، حتى تنفيذ الحسابات والحجز في مراحلهما.

تشغيل الاختبارات الكاملة
1 انسخ .env.testing.example إلى .env.testing وحدد كلمة مرور اختبار محلية خاصة ومختلفة عن التطوير.
2 نفذ docker compose --env-file .env.testing --profile test up -d db-test وتحقق من healthy. هذه القاعدة مستقلة على المنفذ 5433.
3 نفذ php artisan key:generate --env=testing --no-interaction ثم php artisan test --compact.
4 النتيجة المسجلة: نجاح الاختبارات الأربعة عشر، 8 للتشغيل و6 للتكامل مع القاعدة. أعد الأمر للتحقق على بيئتك المحلية.
يوفر .github/workflows/ci.yml التعليمات نفسها في بيئة GitHub Actions عند رفع المشروع لاحقا. لم ينشأ مستودع خارجي ولم تشغل مهمة خارجية في هذه الخطوة.
اجتاز الاتصال والترحيلات والاختبارات الكاملة الفحص، وأغلقت P03. الخطوة التالية P04 للحسابات والصلاحيات وعزل العيادات.
